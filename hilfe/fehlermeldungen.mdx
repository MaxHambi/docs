Wenn der Lagerplatz-Barcode-Generator auf ein Problem stößt, gibt er eine farblich gekennzeichnete Meldung aus. **Rote Meldungen** sind Fehler, die den Lauf sofort stoppen — du musst die Ursache beheben, bevor Schilder erzeugt werden können. **Gelbe Meldungen** sind Warnungen, bei denen der Lauf weiterläuft, du aber trotzdem handeln solltest. Unten findest du jede Meldung mit Ursache und konkreten Lösungsschritten.

## Fehler (roter Text — Lauf stoppt)

<Accordion title='Doppelter Eintrag: "01A02" in Unterkategorie 1 und Unterkategorie 2'>
**Ursache:** Derselbe Lagerplatz-Code taucht in mehr als einer Unterkategorie auf. Die Duplikat-Prüfung läuft kategorieübergreifend — ein Code darf im gesamten Lauf nur einmal vorkommen.

**Lösung:**
1. Notiere den genannten Code und die beteiligten Unterkategorien.
2. Entscheide, in welcher Unterkategorie der Code tatsächlich benötigt wird.
3. Entferne den Code aus allen anderen Unterkategorien.
4. Starte den Lauf erneut.

In der CLI mit `--file` werden zusätzlich die **Zeilennummern** der `.txt`-Datei angegeben, damit du den doppelten Eintrag sofort in deinem Editor findest.
</Accordion>

<Accordion title="Ungültige Lagerplatz-Codes gefunden — Unterkategorie N, Position M: …">
**Ursache:** Mindestens ein Code in der angegebenen Unterkategorie enthält ein unzulässiges Zeichen oder verstößt gegen eine andere Validierungsregel (z. B. zu lang, verbotenes Zeichen).

**Lösung:**
1. Suche im Protokoll nach der genannten Unterkategorie (N) und Position (M).
2. Prüfe den Code auf unzulässige Zeichen — erlaubt sind nur druckbare ASCII-Zeichen (Buchstaben, Ziffern, `-`, `.`, `$`, `+`, `%`, Leerzeichen).
3. Korrigiere den Code und starte den Lauf erneut.
</Accordion>

<Accordion title="Falsches Passwort. Bitte erneut versuchen.">
**Ursache:** Das eingegebene Passwort stimmt nicht mit dem hinterlegten Passwort des geschützten Builds überein.

**Lösung:**
1. Prüfe auf Tippfehler, achte auf Groß-/Kleinschreibung und die Tastatur-Sprache (z. B. Y/Z bei deutschem Layout).
2. Falls das Passwort kürzlich geändert wurde, wende dich an die zuständige Person in deinem Team, um das aktuelle Passwort zu erhalten.
</Accordion>

<Accordion title="Vorschau fehlgeschlagen: …">
**Ursache:** Die Vorschau konnte nicht gerendert werden. Das kann an einer fehlerhaften oder inkompatiblen Vorlage liegen, aber auch an einer ungültigen Konfiguration des Zielbereichs.

**Lösung:**
1. Prüfe, ob die geladene Vorlage eine gültige PNG-Datei ist und sich öffnen lässt.
2. Kontrolliere die Zielbereich-Koordinaten in der Konfiguration — negative Werte oder Werte, die größer als die Vorlagengröße sind, können das Rendering abbrechen.
3. Lade die Vorlage erneut und versuche es nochmals.
</Accordion>

<Accordion title="Vorlage konnte nicht geladen werden.">
**Ursache:** Die PNG-Datei ist beschädigt oder enthält Daten, die nicht als gültiges Bild interpretiert werden können.

**Lösung:**
1. Öffne die Vorlage in einem Bildeditor, um zu prüfen, ob sie korrekt dargestellt wird.
2. Exportiere die Vorlage erneut aus deiner Grafiksoftware als PNG.
3. Lade die neu exportierte Datei in den Generator.
</Accordion>

<Accordion title="Bitte eine PNG-Bilddatei als Vorlage auswählen.">
**Ursache:** Du hast eine Datei in einem anderen Format als PNG (z. B. JPEG, SVG, PDF) in die Dropzone gezogen oder ausgewählt.

**Lösung:** Konvertiere deine Vorlage in das PNG-Format und wähle die konvertierte Datei aus. Viele Grafikprogramme und Online-Konverter können das für dich erledigen.
</Accordion>

<Accordion title="Zeichen an Position N ist kein ASCII">
**Ursache:** Der Code enthält an der angegebenen Zeichenposition ein Zeichen außerhalb des druckbaren ASCII-Bereichs — häufig ein Umlaut (Ä, Ö, Ü, ä, ö, ü, ß) oder ein anderes Sonderzeichen.

**Lösung:**
1. Sieh dir den Code an und ersetze das Zeichen an Position N durch ein zulässiges ASCII-Zeichen.
2. Falls Umlaute aus dem Firmensystem kommen (z. B. Export aus einem ERP), ersetze sie systematisch: `Ä → AE`, `Ö → OE`, `Ü → UE`, `ß → SS` oder kürze den Begriff entsprechend ab.
</Accordion>

<Accordion title="Der Code passt nicht in die gewählte Symbologie (zu lang)">
**Ursache:** Der Code überschreitet die maximale Länge von 48 Zeichen für den Code-128-Barcode.

**Lösung:**
1. Kürze den Code auf maximal 48 Zeichen.
2. Alternativ kannst du die Barcode-Skalierung in der Konfiguration anpassen, um mehr Zeichen in den Zielbereich zu quetschen — beachte dabei aber, dass sehr schmale Balken von manchen Scannern nicht mehr gelesen werden können.
</Accordion>

<Accordion title="Die Prüfziffer stimmt nicht">
**Ursache:** Du hast einen Code eingegeben, der bereits eine Prüfziffer enthält — diese letzte Ziffer stimmt aber nicht mit der automatisch berechneten überein.

**Lösung:** Entferne die letzte Ziffer des Codes. Der Generator berechnet die Prüfziffer für Code-128 automatisch und hängt sie selbst an — du musst sie nicht manuell angeben.
</Accordion>

## Warnungen (gelber Text — Lauf läuft weiter)

<Accordion title="Zielbereich … reicht über die Vorlagengröße … hinaus">
**Ursache:** Die konfigurierten Koordinaten oder Maße des Zielbereichs liegen außerhalb der Abmessungen der geladenen Vorlage. Der Barcode würde teilweise oder vollständig außerhalb des Bildes platziert.

**Lösung (wähle eine der beiden Optionen):**
- **Option A:** Aktiviere in der Konfiguration die Option **„Zielbereich automatisch"** — der Generator passt den Zielbereich dann selbständig an die Vorlagengröße an.
- **Option B:** Passe die Koordinaten und Maße des Zielbereichs manuell an, sodass sie vollständig innerhalb der Vorlagenabmessungen liegen.
</Accordion>

<Accordion title="Config-Datei der Unterkategorie nicht gefunden, verwende globale Konfiguration">
**Ursache:** Für die betreffende Unterkategorie wurde keine eigene Konfigurationsdatei hinterlegt. Der Generator fällt automatisch auf die globale Konfiguration zurück.

**Lösung (wähle eine der beiden Optionen):**
- **Option A:** Lege eine spezifische Config-Datei für die Unterkategorie an, wenn du abweichende Einstellungen (z. B. anderen Zielbereich) benötigst.
- **Option B:** Ignoriere die Warnung, wenn die globale Konfiguration für diese Unterkategorie ausreichend ist — der Lauf wird korrekt abgeschlossen.
</Accordion>

## CLI Exit-Codes

Nach einem CLI-Lauf gibt das Programm einen Exit-Code zurück, den du in Skripten und Build-Pipelines auswerten kannst.

| Exit-Code | Bedeutung |
|-----------|-----------|
| `0` | Alles erfolgreich — alle Schilder wurden ohne Fehler erzeugt. |
| `1` | Ungültige Einträge gefunden oder der Lauf wurde aus einem anderen Grund abgebrochen. Sieh dir die Ausgabe im Terminal an, um die genaue Ursache zu ermitteln. |
