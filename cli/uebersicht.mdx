Die `lager`-CLI ist das richtige Werkzeug, wenn du Barcode-Schilder nicht manuell im Browser erzeugen möchtest, sondern sie in Skripte, geplante Aufgaben oder ein Warenwirtschaftssystem einbinden willst. Du übergibst einen einzelnen Lagerplatz-Code, einen Bereich oder eine ganze Eintragsliste — und bekommst fertige PNG-Dateien zurück, exakt wie aus der Web-App.

## Voraussetzungen

Bevor du die CLI nutzen kannst, stelle sicher, dass folgendes auf deinem System vorhanden ist:

- **Node.js 24** oder neuer — lade es von [nodejs.org](https://nodejs.org) herunter
- **Git** zum Klonen des Repositories

<Note>
  Prüfe deine Node.js-Version mit `node --version`. Die CLI verwendet moderne
  ES-Modul-Syntax und läuft nicht auf älteren Node.js-Versionen.
</Note>

## Installation

<Steps>
  <Step title="Repository klonen">
    Klone das Repository und wechsle in das Projektverzeichnis:

    ```shell
    git clone https://github.com/MaxHambi/Lager-etiket.git
    cd Lager-etiket
    ```
  </Step>

  <Step title="Abhängigkeiten installieren">
    Installiere `pnpm`, falls es noch nicht vorhanden ist, und dann alle Projektabhängigkeiten:

    ```shell
    npm install -g pnpm
    pnpm install
    ```
  </Step>

  <Step title="CLI bauen">
    Erzeuge die ausführbare CLI:

    ```shell
    pnpm build
    ```

    Danach kannst du die CLI mit `node packages/cli/dist/cli.mjs <befehl>` aufrufen.
  </Step>
</Steps>

## Verfügbare Befehle

Die CLI stellt drei Befehle bereit. Eine vollständige Beschreibung aller Optionen und Ausgaben findest du auf der Seite [Befehle](/cli/befehle).

| Befehl | Zweck |
|---|---|
| [`generate`](/cli/befehle#lager-generate) | Erzeugt Barcode-Schilder als PNG-Dateien |
| [`validate`](/cli/befehle#lager-validate) | Prüft Codes auf Gültigkeit und Duplikate, ohne zu rendern |
| [`list`](/cli/befehle#lager-list) | Zeigt unterstützte Symbologien und die aktive Konfiguration an |

## CLI oder Web-App — was passt besser?

Beide Wege erzeugen identische Ergebnisse. Die Entscheidung hängt davon ab, wie du arbeitest:

| Situation | Empfehlung |
|---|---|
| Du erzeugst gelegentlich einige Schilder | **Web-App** — kein Setup nötig |
| Du hast eine Liste mit vielen Lagerplätzen | **CLI** — `--file` verarbeitet beliebig viele Einträge |
| Du willst die Erzeugung automatisieren (z. B. nächtlich) | **CLI** — lässt sich in Cron-Jobs oder Task-Scheduler einbinden |
| Du bindest die Erzeugung an ein Warenwirtschaftssystem an | **CLI** — Exit-Codes ermöglichen saubere Fehlerbehandlung |
| Du möchtest das Ergebnis sofort im Browser sehen | **Web-App** — direkte Vorschau ohne Terminal |

## Tipps für Skripte und Automatisierung

<Tip>
  Prüfe deine Codes immer zuerst mit `node packages/cli/dist/cli.mjs validate --file liste.txt`,
  bevor du einen großen `generate --file`-Lauf startest. So erkennst du
  ungültige Zeichen oder Duplikate, ohne Zeit mit dem Rendern zu verschwenden.
</Tip>

<Tip>
  Nutze die Exit-Codes in deinen Skripten: Die CLI beendet sich mit **0**,
  wenn alles erfolgreich war, und mit **1**, wenn ungültige Einträge gefunden
  wurden oder ein Fehler aufgetreten ist. Das funktioniert direkt als
  Bedingung in Bash-`if`-Ausdrücken oder PowerShell-`if ($LASTEXITCODE)`-Checks.
</Tip>

<Note>
  Die CLI verwendet dieselbe Standard-Konfiguration wie die Web-App. Wenn du
  eine eigene Konfigurationsdatei nutzen möchtest, übergib den Pfad mit
  `--config pfad/zur/config.json`.
</Note>

<Warning>
  Ungültige Zeichen — zum Beispiel Umlaute (ä, ö, ü) — werden vor dem
  Rendern abgelehnt. Es entstehen dabei keine unvollständigen Schilder;
  der Befehl bricht mit Exit-Code 1 ab und benennt die problematischen Einträge.
</Warning>
